## Checks with no bug found

- a) Touch scrolling (Chromium CDP gestures, 390x844, slow and fast, down and up): no jumps, no stuck pin.
- b) After the fix: viewport 844 -> 784 -> 944 -> 844 high mid-story (scrollY 900) and mid-pin (2400): scrollY unchanged, same pin-spacer count, no re-init marker loss. Chromium and WebKit.
- c) Rotation portrait <-> landscape: story and platform fall back to stacked, return to pinned in portrait, no overflow.
- d) Reload keeps position (Chromium); direct load of `#demo`, `#who`, `#platform` lands the title 3px to 56px below the header (header bottom 71px).
- e) Menu links `#who`, `#platform` land below the header, including after the pinned story.
- f) Menu: opens, Escape closes and returns focus, no overflow while open.
- h) Platform on phones: all five tabs reachable and in view, each panel visible, Mobility image `naturalWidth` 1034, ALEF screens mounted.
- i, j) Form inputs 16px, correct types and autocomplete, labels attached, errors visible, 54px high.
- k) `scrollWidth == clientWidth` at every sampled position and size (all 18 viewports, also at 200% text).
- m) JS disabled: all content readable, no overflow. 4x CPU and slow network at 390: CLS 0.0002, no FOUC seen.
- n) 200% text at 390: no horizontal overflow at 13 scroll positions.
- o) Desktop keys: Space 787, PageDown 1574, ArrowDown 1614, End 13631, Home 0; browser zoom 150% (960x600 at DSF 1.5) keeps the pin and has no overflow.
- p) Console and network: zero errors and zero failed requests on every run, local and live (live URL still serves the build from before this round).
- l) Safe areas: `viewport-fit=cover` is not set, so the browser keeps content out of the notch itself in landscape; no `env()` usage needed.
